# 推し活辞書パック 枠組み＋種リスト v0.1

One Keyboard の追加辞書パック（推し活向け、販売フェーズ用）の種リスト。今回は「作る仕組み（枠組み）」と種データまでを置く。アプリへの組み込みは行わない。

## 目的と位置づけ

- このパックは販売フェーズの商品（全部入り買い切りの一部として同梱）であり、想定読者はアイドルファン全般。推し活用語・グループ名・メンバー名を正しい読みで一発変換できることが価値になる。推し活の主戦場は SNS と現場レポであり、最初からスマホ入力の文化であるため、スマホキーボードとの相性が特に良い領域。
- 今回の成果物は **枠組み（整備ルール）＋種リスト** のみ。データの大量投入（流行り層の最新化を含む）とアプリ組み込み（追加辞書チャネル経由の LOUDS 辞書化、設定での辞書ごと ON/OFF、遅延ロード）は **販売フェーズ** に行う前提。

## ユニット構成（3ユニット分割）

辞書は以下の3ユニットに分かれる。**各ユニットは独立して設定で ON/OFF でき、OFF のユニットはロード自体しない**（メモリ・候補検索のコストゼロ）。全部入りで同梱しても、使わないユニットにコストを払わせない。

| ユニット | 内容 | 種件数 |
|---|---|---|
| 推し活（共通・用語） | 推し活用語・現場用語＋汎用略称 | 39件 |
| 推し活（男性アイドル） | 男性グループ／メンバー＋関連用語 | 80件 |
| 推し活（女性アイドル） | 女性グループ／メンバー＋関連用語 | 112件 |

- 用語層（推し活用語・現場用語）は性別を問わないため共通ユニットに入れる。
- グループ／メンバーは性別で男性編・女性編に振り分ける（K-POP グループも同様）。
- そのまま型の略称は、性別固有のものを各編へ、汎用のものを共通ユニットへ入れる。

## 枠組み（整備ルール）

### データの3層構造

| 層 | 内容 | 鮮度 |
|---|---|---|
| (a) 用語層 | 推し活用語・現場用語（共通ユニット） | 腐らない。種として今置いてよい |
| (b) 長寿グループ層 | 長年活動し定着したグループと、その代表的メンバー | 安定。卒業・脱退の反映のみ販売時に確認 |
| (c) 流行り層 | 最近の流行りアイドル（グループ＋主要メンバー） | **腐りやすい。全件に「販売時に要再確認」の鮮度フラグを付けるルール**とし、販売直前に最新化する運用 |

- 流行り層の鮮度フラグは、テーブルではグループ行のメモに明記する。流行り層のメンバー行も全て同フラグの対象とする。
- メンバー構成は入れ替わりが前提（卒業・加入・脱退・活動休止）。長寿層でも販売時に現行体制と突き合わせる。

### 読み付けルール

- **公式読み優先**。グループ名・メンバー名は公式サイト／公式表記のふりがなを正とする。
- **メンバー名は読みに確信が持てる場合のみ収録**する。確信が持てない読みは推測で書かず、「要確認」を付けるか収録しない（この辞書は読みの正確さが価値そのもの）。
- グループ名は英字表記にカタカナ読みを付ける（例: すのーまん → Snow Man）。略称（スノ、きんぷり等）も変換型の別行として登録し、メモに「略称入力」と明記する。
- 「・」「！」「♡」「=」等の記号は表記列の正式表記に保持し、読みからは除く（例: ちょうときめきせんでんぶ → 超ときめき♡宣伝部）。
- ステージネーム表記のメンバー（HANA、BE:FIRST、ME:I の活動名等）は、カタカタ読みから英字ステージネームへの変換として登録する。本名が広く知られる場合は本名行を併記する。

### 変換時の扱い

- パックの候補は **通常辞書より低優先** にする（既定の設計）。日常会話の変換に固有名詞が割り込むノイズを防ぐ。
- 設定で **ユニットごとに ON/OFF** できる。**OFF のユニットはロード自体しない**。
- 初期状態（デフォルト ON/OFF）は販売時に最終判断する。

### 権利メモ

- グループ名・個人名は、変換辞書の **見出し語としての収録**（事実の参照）にとどめる。写真・ロゴ・歌詞等の著作物は含めない。
- 商標・グループ名の表記は正式名称をそのまま表記列に使う。

## エントリの型とテーブルの見方

エントリには2つの型がある。

1. **変換型** — かな読みを打つと表記が候補に出る（例: おし → 推し）。種リストの主体。略称からの変換（例: すの → Snow Man）も変換型の行として収録し、メモに「略称入力」と記す。
2. **そのまま型** — 英字略称などを打つと、その表記がそのまま候補に出る（例: FC → FC）。各ユニットの末尾にまとめる。

| 列 | 意味 |
|---|---|
| 読み・入力 | 変換型はかな読み、そのまま型は入力パターンそのもの |
| 表記 | 候補として出す表記 |
| メモ | 補足。「要確認」は販売前に検証が要る項目、「販売時に要再確認」は鮮度フラグ対象 |
